## 2. 本轮范围：真实可操作的地图骨架

以现有「附近」Tab 为主入口，复用海港青、卡片圆角、文字层级、底部悬浮 Tab 与 Safe Area。

### A. 位置选择

- 默认不请求定位权限。首次无选择记录时可使用**明确标注为默认浏览区域**的 `中環`（使用仓库现有经过核对的香港地标坐标；不能写死未经核验的经纬度）。
- 提供手动选择区域，**优先复用** `src/nearby-bus-landmarks.ts` 里已有的七个核对过的地标和现成的坐标/标签；若需要名称展示兼容“中環”，可使用中環碼頭或对应已核实参考点，并标明用途。
- 用户明确点击「使用我的位置」时才进行前台授权/单次定位。复用现有 `expo-location` 及 `nearby-bus-location` 的拒绝、超时、精度不足、香港境外判断。不要后台跟踪，不存储精确设备坐标，也不自动把手动选区误认为设备位置。
- 手动地区、设备定位来源、当前相机中心这三个概念分开建模；拒绝/失败时继续可手动浏览。

### B. 地图与列表

- 首页默认**地图模式**；顶部清晰呈现当前区域、使用我的位置、类别横向筛选，以及双向可见的「地圖／列表」分段控件。
- 分类固定：`全部／公廁／寵物公園／公園／巴士`。前四项按未来 Facility 分类筛选；「巴士」跳现有 `/bus/nearby`，保护原有查询条件，不实现重复巴士数据。
- 地图使用 `react-native-maps`，**使用 SDK 57 兼容安装命令 `npx expo install react-native-maps`**，iOS 使用默认 Apple Maps，不引入 Google Maps API key；先检查项目是否已有库再决定是否安装。地图失败时给明确状态并可切到列表。
- 地图缩放/平移、标记、选中底部卡、查看当前地区、地图/列表切换均是真实 Pressable/MapView 交互，不能只画静态样式。
- 地图/列表共用同一筛选状态与选中地点身份；在页面内切换视图不重复申请位置、不重置筛选或选择。切换 Tab 再返回时尽力保存地区、视图、类别和地图相机/滚动状态。
- 避免触控被悬浮 Tab、底部地点卡和 iPhone Home Indicator 遮挡；列表必须能滚到最后一个项目。
- 地图标记颜色按已核验的设施类别映射，不依赖标记颜色推断设施许可。选择标记弹出轻量卡：名称、类别、地区或地址（若有）、资料来源；未核实字段不展示。点击别处或关闭可收起。
- UI-04A **不实现新的完整详情页**；如已有统一详情路由，可保持入口模型但不可指向假数据或无用空白页。完成 UI-04B/C 后再连真实设施记录；UI-04D 实现完整详情。

### C. 数据边界与骨架

- 创建最小可扩展的 `Facility` 类型/适配层，包含稳定来源身份（source + officialId）、标准类别、`zh-HK`/English 名称、可选地址、合法 WGS84 坐标、原始来源与更新时间；可选字段不应被填充伪值。
- **UI-04A 不抓取/录入实际 FEHD/AFCD/LCSD 全量数据**。那是后续 UI-04B、UI-04C 的工作；不要为了让 UI 看起来有内容而造设施数量、距离、开放状态、图像、规则或地点分类。
- 若真实正式数据为空，地图仍可浏览，列表显示清楚的「官方設施資料待接入」阶段空状态，不能把灰色骨架当作永远 Loading。示例 marker 只能在独立的受保护测试 fixture 中用于检查联动，默认生产数据源必须为空且不能展示示例。
- 列表有真实资料时按所选参考点与站点坐标的 **Haversine 直线距离**排序，并标注“直線距離／距離參考點”，不冒称步行距离；仅有效且真实坐标可参与排序。
- 不因 UI-04A 强行升级 SQLite schema；如果为了后续设施真的需要迁移，必须是单向前进迁移、保留现有天气/巴士/收藏数据，并报告为什么不能延后到数据接入阶段。
- 本地图数据可离线读取，但不承诺 Apple Maps 地图瓦片离线可用；地图不可用时列表状态与数据仍可处理。

### D. 保持旧功能和双语

- 保留现有首页「公廁／寵物公園／公園」快捷入口含预选分类参数；保留「巴士查詢」与现有附近巴士完整功能；不要把它们改成无反应的按钮。
- 保留「首頁／附近／探索／收藏」四个浮动 Tab、天气胶囊与警告、巴士 ETA、收藏页、搜索页以及当前主题。
- `zh-HK`/English/跟随系统，英文较长标签可以横向滚动类别，不剪切文本；地图错误、拒绝位置及空态都有双语文案，VoiceOver 可读。
