# Phase 5A3 · 附近交通「全部」聚合修复

## 根因与复现

原页面只在单独的「專線小巴」分类运行 `nearbyGmbRows`。「全部」的候选列表也只合并巴士和铁路。两条路径分别遗漏了查询和聚合，所以按路线和按车站都拿不到附近小巴。港铁、轻铁已有聚合逻辑；未发现异步覆盖、按类型截断或分页导致这次遗漏。

固定复现使用元朗轻铁站（ID 430）的官方坐标及 500 米范围。修复前新增断言实际取得 0 个小巴路线方向，离线快照预期有 14 个。修复后「全部」纳入全部 14 个合格小巴路线方向；按车站也纳入同一范围内的 14 个合格小巴站。两种模式、三档半径均逐项比对了「全部」和单独小巴分类。

## 修改文件与行为

- [附近交通页面](../src/app/bus/nearby.tsx)让「全部」和小巴分类共用离线小巴查询；「全部」把巴士、港铁、轻铁和小巴候选合并后，按未四舍五入的直线距离排序，同距用现有稳定行键决定顺序。被动 GPS 更新期间，共用仍在显示的巴士参考点，随后一起切换到新参考点。
- [小巴离线索引](../src/nearby-gmb.ts)显式区分有距离的附近结果与可以无距离的站名搜索结果。最近上车站选择、路线与方向 ID、站点 ID、站序及循环停靠沿用索引逻辑。
- [附近交通回归](../scripts/test-nearby-bus-location.cjs)覆盖聚合、身份、距离、三档范围、地标、巴士读库失败、延迟加载和快速切换；更新了因合并后排名变化而需要另选的滚动锚点夹具。

附近列表当前使用 FlatList 虚拟渲染。完整排序数据一次交给虚拟列表，无额外网络分页、每类截断或交通类型置顶。小巴沿用现有卡片和详情入口。只有巴士行参与既有列表 ETA 可见性机制；小巴附近查询不发送 ETA 请求。渡轮预览路径、电车门禁及文字搜索沿用原逻辑。

## iPhone 人工验收

1. 打开「附近交通」，在有小巴覆盖的地区定位，或手动选择元朗。分别检查「全部」和「專線小巴」的按路线及按车站，确认在 500 米、1 公里和 2 公里内均可找到合格小巴结果。
2. 在「全部」向下滚动，按各行实际直线距离查看不同交通。小巴较远时可能出现在后面。点小巴路线，再试展开小巴站点选择一条上车服务，核对详情的方向和站序。
3. 用飞行模式及手动地标查看离线结果，恢复网络后快速切换分类，确认列表不串类。切换繁中／英文，核对紧凑工具栏、距离菜单和信息说明。
4. 抽查首页下拉刷新、Tab 左右滑动、详情返回，以及正式环境中电车隐藏和渡轮不可用。

小巴覆盖取决于随包快照和所选半径，距离较远的结果可能需要滚动。实际 iPhone 列表性能、GPS 更新及交互观感待验收。
