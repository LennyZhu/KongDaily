## 3. 三套坐标与状态模型必须分开

- `visibleRegion`：地图当前正在展示的视口；由地图浏览手势和程序化移动变化。
- `committedSearchCenter`：**已确认的**搜索中心；列表距离和排序以它为准。
- `deviceLocation`：最近一次成功且通过校验的 GPS 定位（只在内存中）。
- `selectedFacilityKey`：设施身份，原格式 `source + officialId`；不得用名称代替。

选择已核验地标或点击顶部定位成功：直接更新 `committedSearchCenter` 并调整地图视口。  
**自由拖动地图：只更新 `visibleRegion`，不直接更新 `committedSearchCenter`。**  
点击地图上浮现的 `搜尋此區域`：把有效地图中心提交为新 `committedSearchCenter`，再更新附近结果/距离/列表排序，并清除待确认提示。

## 4. 定位与权限

- 首次进入且**已有前台授权**、没有需要恢复的当前会话状态时：允许单次定位成功后更新搜索中心。
- 未授权/拒绝/系统关闭：**不得首次进入便弹权限框**；用当前会话保留状态或默认「中環碼頭」，用户可以浏览、手动选择地标。
- 点击顶部定位按钮时，才按需申请前台权限和定位一次；不得引入常驻、后台定位或持续上传。
- GPS 坐标校验、精度不足、超时、境外、不可信坐标等继续沿用既有逻辑。
- 迟到的定位结果不能覆盖之后发生的用户拖动、地标选择、设施选择、切换 Tab 等操作；使用请求代数/取消标记保护。
- 返回附近 Tab、从外部地图导航返回或从设施页返回时，保留当前会话的地图中心、搜索中心、分类和选中，不自动跳回 GPS。

## 5. 地图「搜尋此區域」

- 仅在**明确的用户地图拖动或缩放结束、变化超过合理阈值**时出现地图上方的小胶囊 `搜尋此區域`／`Search this area`。
- MapKit 的 `onRegionChangeComplete` 第二参数 `isGesture` **不可作为 Apple Maps 的可靠手势来源**；应结合程序化 `animateToRegion`/视口恢复的标记、用户触摸/相机变化和容差/防抖处理。不得形成 controlled-region 死循环。
- 切换地图／列表本身、程序化中心更新、标记点击／选中设施、回到前台、视口恢复等不应误出现。
- 选择已核验地标／顶部 GPS 成功时，视口调整后不应该还留下「搜尋此區域」。
- 不允许把超出香港服务范围的中心当作合法香港搜索结果；要显示双语说明并保留上个有效搜索中心。
- MapKit 手势识别若有尚未能可靠解决的原生边界，必须**诚实报告**并列为模拟器验收项。

## 6. 列表搜索中心说明

- 地图与列表**共用** `committedSearchCenter`。
- 列表顶部一行**低干扰**文字即可，例如 `搜尋中心：中環碼頭 · 按直線距離排序`，如果中心来自 GPS 显示 `目前位置`，如果来自主动点击「搜尋此區域」显示 `地圖中心`。
- 仅拖动地图但尚未按「搜尋此區域」时，切换列表仍沿用上一已确认搜索中心；不可悄悄更改基准。
- `source+officialId` 选中及列表展开状态按原规则延续，不假选中其它设施。
