# UX-01B 附近巴士限定服務時間與 ETA 狀態

## 根本原因

「附近巴士 → 按路線」以已收錄的車站、站序和路線選項找出建議上車站，再由 `useStationEta` 按可見卡片向營辦商查詢。九巴及龍運共用站點 ETA 端點。解析時按路線、方向、服務類型、站序及回應提供的站點 ID 篩選。原有列表沒有資料可解釋路線是否只在指定時段服務。

原判定以符合條件的最新 `data_timestamp` 為主，沒有可用項目時間時才使用回應的 `generated_timestamp`。`receivedAt` 是 App 收到回應時記錄的設備時間。`etaIsStale` 將設備當前時間與較早的資料時間或接收時間比較，滿 120 秒即過期。這個期限適合有時間的預報及已久未更新的回應。原程式也讓空 `eta` 的列參與這項判定，因此一次新回應內的舊空列可以讓卡片錯誤顯示「到站資料已過期」。反過來，同次回應內的新空列也可能令舊預報取得較新的摘要時間。九巴的 `generated_timestamp` 表示回應最初產生的時間，列級 `data_timestamp`、`eta` 和雙語 `rmk_*` 各自代表不同資料。 [九巴 ETA API 規格](https://data.etabus.gov.hk/datagovhk/kmb_eta_api_specification.pdf) · [資料字典](https://data.etabus.gov.hk/datagovhk/kmb_eta_data_dictionary.pdf) · [DATA.GOV.HK 站點 ETA](https://data.gov.hk/en-data/dataset/hk-td-tis_21-etakmb/resource/12185102-718d-4d03-bfd7-b9ecf760aee2)

以構造回應重現了新回應配舊空列的誤判。沒有回饋當刻的 API 回應、設備時間或輪詢紀錄，無法將當時每張卡的過期訊息歸因至同一原因。普通路線也可能在營辦商資料久未更新、卡片離開可見範圍或重新查詢失敗後，顯示真正過期的最後一次回應。正式資料樣本核查時，普通 258D 和 261 有新鮮預報。

表內時間是供核查的常規起站時間。App 只儲存已核實的路線身分和官方時間表連結。仍缺乏分站到站時間、臨時營運安排和足以執行的學校假期規則。App 因此不依手機日期計算「現時非服務時段」、下一班計劃時間或任何假期結論。官方時間表可從詳情開啟，僅在使用者點按時交由系統瀏覽，開啟失敗時有雙語提示。

## ETA 顯示規則

| 狀態 | 附近巴士按路線顯示 |
| --- | --- |
| 有新鮮、仍未到時的預報 | 繼續顯示倒數及有效的營辦商備註。 |
| 回應新鮮但沒有可用預報 | `暫無到站預報` / `No arrival estimate available`。包含空回應、沒有符合所選方向及站序的資料、空 ETA，及只剩已過到站時間的情況。當期的營辦商備註仍可另行顯示。 |
| 真正過期 | `到站資料已過期` / `Arrival data has expired`。九巴／龍運有到站時間時，以相符預報的資料時間判定，每列另有期限。沒有到站時間的回應則用回應產生時間，缺失時用接收時間，過期備註不當成現況展示。 |
| 重新查詢失敗 | 無可用預報時顯示更新失敗並附具體錯誤。如果最後一份資料也已過期，保留過期標示和更新錯誤。尚有效的預報仍可倒數並附更新錯誤。 |

限定服務提示獨立顯示 `只在指定日期或時段服務` / `Operates on selected days or at specific times`。查詢端點、輪詢、距離排序和正式站點資料沿用原有流程。

## iPhone 人工驗收

1. 已授權定位後開啟附近巴士。使用定位或合適的現有地標找出 258P 和 261P，確認按路線結果及建議上車站仍正常。可在洪水橋附近查找兩條路線。用巴士查詢分別開啟 258P 雙向及 261P 往上水天平方向以驗證官方時間表入口。
2. 在營辦商未提供 ETA 時，確認符合的卡片同時顯示限定服務提醒及「暫無到站預報」。有 ETA 時確認仍倒數。用普通 258D 或 261 對照，確認沒有新增限定服務提示。
3. 在有 ETA 的卡片測試網絡中斷及恢復，區分更新失敗和資料過期。恢復網絡後核對可取得新預報。確認位置已授權時，返回「附近巴士」仍會自動取點。
4. 切換繁中和 English。核對較大字體下的卡片提示及官方時間表入口；確認按車站、路線圖、站點詳情、收藏及首頁常用路線正常。
