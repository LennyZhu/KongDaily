## 資料身份與刷新

- 地圖標記和站序列表共用現有選站狀態。卡片用 `describeBusVisit` 組合現有官方路線與停靠資料，由 `busStopEtaHref` 產生完整詳情參數，再以詳情頁使用的 `readEtaTarget` 校驗相同參數。九巴／龍運保留方向與服務類型，城巴保留方向與含前導零的 stop ID，嶼巴保留路線 ID 及重複停靠旗標。完整詳情沿用 Expo Router push，原地圖選站留在 Stack。
- 預覽以完整 ETA 身份掛載，採用路線詳情同樣的 350 ms 防抖；等待期間即顯示查詢狀態。快速切站會清除前一站的防抖或中止其在途查詢。現有 Hook 只在前景及畫面聚焦時輪詢，每 60 秒按需查詢當前站，手動刷新至少間隔 10 秒。路線地圖共用現有格式的請求冷卻表，沿用 URL 冷卻與營辦商 429 冷卻。再次點選同一站時保留原記憶體預報與刷新排程，從完整詳情返回同樣沿用已有結果。[ETA Hook](../src/bus-eta-hooks.ts)
- 底卡沿用 `describeEta` 與營辦商適配器，顯示最早有效班次。即將到站、無預報、方向或停靠不匹配、僅有備註、更新失敗和過期均使用共用狀態。滿 120 秒的舊資料隱藏倒數，保留原資料時間。營辦商回傳 HTTP 404／501 時顯示暫未能提供資料；無效停靠身份會停止查詢。網絡等錯誤顯示原因，重試僅對當前站有效，且受既有冷卻限制。嶼巴官方 ETA 以全站回報，重複停靠時保留原有提示。[ETA 校驗及狀態](../src/bus-eta.ts)

## iPhone 人工驗收

1. 開啟九巴 268X 的去程服務類型 3。點地圖標記核對站序、路線號、站名、查詢狀態及下一班。用下方站序選另一站並快速交替，核對預報和站名一致。
2. 點「查看所有到站時間」，核對詳情的方向、服務類型及站名。用原生返回核對選站仍在，並在詳情測試收藏和首頁置頂。
3. 用九巴 10 或 296A 的站序分別選同座標的首末站，核對兩次停靠的站序及完整詳情身份。用 B2 確認依營辦商資料顯示重複停靠限制（如適用）。
4. 模擬斷網或等資料過期，核對卡片仍保留站點、時間或錯誤，恢復網絡後可重試。無班次路線應顯示暫無資料。
5. 檢查繁中、English、大字和 VoiceOver，確認卡片可捲動、站序仍可操作，且兩個入口易於點選。既有官方線和站點圖仍照核實情況顯示。

畫面尺寸、原生 VoiceOver、MapKit 點按和營辦商即時回應由 iPhone 人工驗收。本輪交付留在工作區，無模擬器、真機、提交、推送或合併操作。
