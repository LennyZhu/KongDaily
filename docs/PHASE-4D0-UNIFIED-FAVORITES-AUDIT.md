## 1. v10 实际 Schema 与行为

| 对象 | 实际约束与语义 |
| --- | --- |
| `bus_favorites`（v5） | 文本 `id` 主键。巴士来源、方向、正数站序和重复停靠标志有 CHECK，运营商需要的组合由 Repository 解码校验。业务键编码来源、路线身份、停靠序号和站 ID。KMB／LWB 包含方向及班次类型，城巴包含方向，新大屿山巴士使用官方路线 ID。保存使用 `ON CONFLICT(id) DO NOTHING`。旧 `pin_order` 仍在表中并有 1–3／唯一约束，只供 v10 旧版导入。 |
| `railway_favorites`（v9） | `mode` CHECK 只允许 `mtr`／`light_rail`。复合主键 `(mode,line_id,station_id)`，线路和站点 ID 非空。保存前验证该线路确实服务该站，按复合主键拒绝重复。收藏代表全线路在该站的服务，跨方向及月台。旧快照可读，资料已下架时仍可删除。 |
| `home_transport_pins`（v10） | 全局 `position INTEGER PRIMARY KEY CHECK 1..3`，数据库最多三个不同位置。共用 `mode` CHECK 仅允许巴士／两铁路。互斥列形状 CHECK，`bus_id` 唯一，`(mode,line_id,station_id)` 唯一。**没有外键，也没有禁止插入孤立引用的数据库触发器**。正常置顶由 Repository 查目标存在。两条收藏删除触发器直接删相应置顶。 |
| `facility_favorites`（v8） | 设施以 `(source,stable_facility_id)` 为键，使用独立表和流程。Saved 的地点分类沿用这套数据。 |

应用首次需求时开 `kongdaily.db`，根层语言读取通常就会触发。启动共用一个 Promise，先用 Expo SQLite 的独立连接事务按 `PRAGMA user_version` 顺序运行历史步骤；同版跳过，较新版本拒绝打开。失败回滚、关闭连接并清除 Promise 供重试。v10 先把 v5 巴士置顶按旧序压紧搬入，再按 `created_at DESC, mode, line_id, station_id` 确定性补至多两条铁路，且总数不超过三。升级后首页仅按 v10 关联表取序。收藏与置顶分离。 [Schema](../src/database.ts) · [巴士 Repository](../src/bus-favorites.ts) · [铁路 Repository](../src/railway-favorites.ts) · [旧业务键](../src/bus-stops.ts)

所有交通收藏写入与置顶操作使用同一 JS 队列。置顶、取消、移动在事务中读取全局排序并按 `1..N` 回写。上移／下移与全局邻居交换，筛选后仍如此。删除触发器和提交后的内存快照更新保证正常删除释放位置；删除可能留下数据库位置空洞，界面按排序后的数组显示连续序号，后续实际改写再压紧。已有三项时返回满额，重复操作不新增。孤立置顶如果出现在外部拷贝或异常写入中，会进入 `readHomePins`，可能占槽但首页没卡；这项风险由源码推导，正常应用流程的存在性检查已有测试。 [置顶 Repository](../src/home-transport-pins.ts) · [Saved](../src/app/%28tabs%29/saved.tsx) · [首页](../src/app/%28tabs%29/index.tsx)

**恢复边界。** 未找到应用自有备份导入、导出或数据库热替换功能。现有测试对已关闭的数据库做副本并重开，证明本地副本模式；iOS 恢复是否提供完整可用的数据库由系统决定。收到有效旧版文件后，下次打开走相同迁移链和版本判断。iOS 恢复路径、WAL 一致性与更高版本降级尚无真机证据。 [已有迁移与副本测试](../scripts/test-facility-favorites.cjs)

## 2. 新交通身份与恢复规则

| 模式 | 唯一业务身份 | 恢复、变化及首页 |
| --- | --- | --- |
| 绿色专线小巴 `gmb` | 香港运输署 `route_id + route_seq + stop_id + stop_seq`。现有 `gmbVisitKey` 的四值足够。地区、显示编号、普通／特别班次描述为快照资料。 | 跨区同号与特别班次由官方 `route_id` 区分，两个方向与同一个循环站的不同停靠各自保留。保存用户实际选中的可上车停靠。查询官方方向站序，核对 `stop_id` 和 `stop_seq`；附近离线旧索引仅作候选。两键冲突、出现多个候选或站序已重排时保留旧收藏并提示重新选择，禁止按同名或只按最接近序号自动改绑。暂时离线与确认失效分开处理。 |
| 电车 `tram` | 运输署命名空间的 `routeId + directionId + stopId + stopSequence`。官方站 ID 区分同名实体，序号区分未来相同实体的多次停靠。 | 保存和直达详情前核对官方方向、站序和上车资格，沿用 4C2 的精确参数。数据更新后如同 ID 改序，默认保留并要求确认，尤其跑马地。石塘咀已保存收藏保留，显示关闭与公告；可展示静态线路、方向及站点。未知须明确未核实。 |
| 渡轮 `ferry`（附条件） | `operatorId + operatorRouteId + directionId + originPierId`，对外 `routeId` 用营办商命名空间。 | 验证方向存在且 `originPierId` 与官方出发泊位一致。中环 4 号与 6 号西泊位分开；别家可能复用数字 ID。泊位或营运变化标记核对，不按目的地／同名替代。只有获准后进入正式库。 |

双语路线及站点快照、保存时间与来源版本用于离线回读、解释状态和比较目录变化，不参与去重。保存与验证现有身份时使用官方 ID 和源新鲜度。无有效新证据时保留收藏；允许显式选择替代停靠，作为独立用户操作处理身份与置顶名额，避免后台把已有收藏改绑。小巴目前按三值 `route_id/route_seq/stop_seq` 请求 ETA，另核对响应的 `stopId`。循环站的响应无法证明具体停靠归属时，延续 4A1B 的保守呈现。 [小巴适配器](PHASE-4A1A-GMB-DATA-ADAPTER.md) · [小巴停靠与 ETA UI](PHASE-4A1B-GMB-SEARCH-DETAIL.md) · [电车状态](PHASE-4C1-TRAM-DATA-ADAPTER.md) · [渡轮身份](PHASE-4B1-HKKF-DATA-ADAPTER.md)

## 3. 建议的前向迁移

1. **v11 添加新交通收藏。** 添加 `transport_visit_favorites`，仅接收 `gmb`、`tram`。使用稳定且规范的键、独立类型字段和 `UNIQUE(mode,route_id,direction_id,stop_id,stop_seq)`。正整数及存储类型检查，两个模式的方向值按现有官方契约 1／2 校验。路线存在、该方向及站序对应、站点可上车仍由适配器核验。保存原双语快照和时间，禁止把名称或 ETA 对象写入键。
2. **替换小关联表。** 新 `home_transport_pins` 继续用 1–3 位置主键，旧巴士列和铁路复合列原义保留；添加新收藏键，与 `mode` 唯一绑定。CHECK 只允许对应模式的一组非空引用，所有其他引用列为空。保存／置顶／移动都复用现有队列。收藏表原行、旧 `pin_order`、时间、服务键和其他数据表均无需重写。
3. **事务内预检、搬迁和核对。** 检查旧置顶形状及真实目标、确定性按 `position` 搬入，必要时压紧旧空洞但保持相对顺序。逐行检验相同业务身份及顺序，包含零项、满三项和混合三项。先明确处理旧表删除触发器，再换表并为三种引用路径重建删除触发器；添加置顶 INSERT／UPDATE 的目标校验，新收藏按不可变键使用。避免旧触发器被 SQLite 自动改指暂存表。最后按审核后的副本核对行数、顺序及完整性，成功才设置 `user_version=11`。预检遇到已有孤立或损坏关联就停止并保留原库，交由明确恢复方案处理；不静默删除。打开失败不得自动用空白收藏库替代。
4. **约束与并发。** 推荐使用目标校验和删除触发器覆盖旧表的多态引用，不假设 v10 已启用 FK。若为新分支增加 FK，须在每个连接开始事务前启用并验证；安装的 Expo SQLite `withExclusiveTransactionAsync` 另开连接，不能只在主连接或已开始的事务里设置 `PRAGMA foreign_keys`。收藏取消时在同一事务压紧剩余三个以内的位置，使用读出并重写避免逐行移动触发唯一冲突。仅在提交后发布 UI 快照，失败重试从数据库读。 [Expo SQLite 本地实现](../node_modules/expo-sqlite/src/SQLiteDatabase.ts)
5. **首次升级、恢复及后续渡轮。** `user_version` 为相同版本时不重复导入。恢复 v8／v9／v10 的有效副本按历史逻辑抵达 v11，再迁移一次；恢复 v11 副本保留现有次序。更高版本继续拒绝降级。渡轮获准后另行审议迁移，例如 v12 增加 `ferry_favorites` 和相应受约束的置顶引用，仍共用原三位置。v11 正式表对白名单外模式失败封闭。历史迁移各段保留原样。 [现有事务入口](../src/database.ts)

## 4. 首页、收藏页及渡轮隔离

- 延用详情的书签入口，绑定具体方向和停靠，属于只下车的停靠不能当作新上车收藏。Saved 增加所支持的分类，沿用横向过滤、首页次序、短置顶／取消置顶按钮和更多菜单。保留置顶与收藏分离、跨类别相邻移动、满额提示和至少 44 × 44 pt 的触达区域。繁中与英文显示状态，VoiceOver 读出类别、路线、方向、站点、已置顶位置及禁用操作。
- 首页继续消费一份全局顺序并以稳定键渲染。既有公交和铁路 ETA 链沿用。小巴只刷新有资格的可见置顶，以精确停靠及已验证来源使用官方临时缓存，按现有生命周期、合并、超时及退避，后台或失焦停止新请求。失效或暂不可验证的收藏保留卡位，显示相应提示并可取消置顶。小巴发布前仍复核官方端使用、缓存及再利用证据。电车先显示静态方向、站点及运营状态，关闭时可链接公告，未知不显示已核实。获正式 ETA 后以单独读层映射旧键，不改收藏库身份。 [4A0 来源审计](PHASE-4A0-TRANSPORT-DATA-SOURCE-AUDIT.md) · [电车授权审计](PHASE-4E0-TRAM-ETA-LICENSING.md)
- 渡轮 UI、Repository、读写、首页投影、深链接及未来备份导入均复核同一提供者资格。已存在的 HKKF 开关要求 `__DEV__` 和明确的预览变量，客户端默认关闭。开发预览用进程内收藏和独立测试槽位；如需验持久化，使用独立开发容器与排除备份的测试库，生产不可读取或迁入。生产 v11 Schema 无渡轮收藏模式；对外来备份、深链及非法模式采取拒绝，不创建客户端，也不展示预览标签或数据。权利确认后有单独的生产发布准入；授权撤回时保留用户键和退出／取消选项，只停止数据访问并屏蔽受限快照，且不自动替换原置顶。 [当前预览开关](../src/hkkf-preview.ts) · [渡轮授权与导出核验](PHASE-4B3-HKKF-NEARBY.md)
- 获准渡轮首页首选有来源的「計劃開航」，保留香港服务日、跨午夜和未知日型规则。将来若获准实时字段，单独显示「船舶預計抵達」，不能混称乘客下一班开航。 [渡轮时刻表与许可](PHASE-4B2-HKKF-SEARCH-TIMETABLE.md)

## 5. 4D1–4D4 与验收门槛

| 阶段 | 任务及验收重点 |
| --- | --- |
| **4D1 基础** | 评审 v11 草案，实施新增表及关联表原子升级、统一读写与测试。用 v8／v9／v10 的关闭副本及新安装核对原收藏、时间、设置与顺序；不同位置数量、空洞、三项满额、重复启动、同版本恢复和较新版本拒绝。注入搬迁、删旧触发器及设置版本前失败，逐项验证回滚后原数据库及版本完整。 |
