# KongDaily · UI-05B 探索精選地點設計審閱

KongDaily 1.0 採用方案 A「精選地點」。首批以 8–12 個可用官方資料核實的地點為目標，發佈範圍以逐筆審核結果為準。列表及詳情會隨 App 提供離線閱讀。活動、購票、評價、AI 推薦、照片上傳、探索收藏、地圖探索及後端均延期。

本稿以 `develop` 的 `8c53b9ad85e74faf418559d51b87e8078edf2028` 為基線。UI-05A 報告在工作區為未追蹤檔案，原樣保留。現有探索 Tab 支援 `category` 參數並只顯示空狀態。本設計保留這套分類語義及四個主 Tab。路由及視覺規格供 UI-05C 審閱使用。[UI-05A 審計](UI-05A-EXPLORE-AUDIT.md)、[探索 Tab](../src/app/%28tabs%29/explore.tsx)、[首頁](../src/app/%28tabs%29/index.tsx)、[根 Stack](../src/app/_layout.tsx)、[雙語字典](../src/i18n.ts)、[設計 Tokens](../src/theme.ts)

## 2. 探索首頁與分類

從上至下為 `探索 / Explore`、一行簡介、兩列四類篩選、列表標題與地點卡片。簡介提案為「發掘香港值得一去的地方。」／“Discover places worth visiting in Hong Kong.”。預設標題為「精選地點」／“Featured places”。選中一類後，列表標題使用該分類的現有名稱。頂部隨內容捲動，底部沿用現有懸浮 Tab 與內容安全間距。

| 路由值 | 繁中／English | 首版選入條件 |
| --- | --- | --- |
| `parks` | 公園休憩／Parks & leisure | 有具體遊覽亮點及可核實資訊的休憩地點。普通公園查找繼續由附近負責。 |
| `hiking` | 行山郊遊／Hiking & outdoors | 可清楚界定的一條官方行山路線或郊遊地點。 |
| `waterfront` | 海濱景點／Waterfront spots | 可指明範圍的海濱景點，附已核實的到達資訊。 |
| `pets` | 寵物友善／Pet-friendly | 有官方資料支持寵物同行的精選去處，僅按已核實規則與適用範圍描述。附近仍提供寵物公園搜尋。 |

選中分類時，列表標題右側顯示「查看全部」／“View all”。點按會清除分類並恢復全部精選。預設未篩選時隱藏這個入口。四類維持單選且可取消。選中使用 `colors.tint`、`colors.primary` 邊框及文字和勾選符號，未選中使用白色與標準邊框。再次選中相同分類也會清除篩選。空分類同樣保留標題右側的「查看全部」。缺少相應資料時保留分類。每個地點只有一個主要分類用於卡片展示，可在證據支持下納入其他分類。列表以固定編輯排序顯示，同一地點在總覽只出現一次。地區是描述欄位。

### 卡片規格

- 全卡為單一進入詳情的觸控目標。左側為約 66×66pt 的類別插畫或 SF Symbol 色塊，右側依序顯示 17–18pt 的名稱、12–14pt 的「類別 · 地區」及 14pt 的一句特色。最右保留箭頭和內距。卡片沒有第二個操作。
- 外框用 `colors.surface`、`colors.border` 和 `radius.card`。標準頁面邊距 20pt，卡片內距 12–16pt，卡片間距 12pt，主要區塊間距 24pt。列表牌高約 98pt 為一般字級示例，內容可以撐高行。缺地區時省略該欄及分隔符。
- 無照片為正式版型。以既有海港青、園景綠、海濱藍色塊，配抽象山形、波紋或原有類別圖示辨識。圖案由此設計自行繪製，沒有具體地理意義。未取得可本地分發及裁切的照片權利前，沿用無圖方案。App 無載圖失敗框、空白照片區或網絡圖片依賴。

## 3. 地點內容詳情

由根 Stack 推入「地點詳情」／“Place details”，使用與巴士詳情一致的淺青標題列及原生返回。詳情頁由上至下為類別、地區、地點名稱、類別插畫、精簡特色介紹、精選看點、交通及注意事項、官方資料及合資格的導航按鈕。沿用普通捲動，正文 17pt、輔助資訊 14pt，連結列至少 44pt 高。導航放在正文底部，隨內容捲動。

| 資訊 | 顯示規則 |
| --- | --- |
| 特色及地區 | 一至兩句自撰介紹，讓用戶知道值得去的理由。路線與場地名稱按實際官方身份顯示。 |
| 精選看點／Highlights | 放在簡介之後、交通與注意事項之前。每處優先顯示 2–3 條經官方資料核實、有具體遊覽價值的看點。證據不足便暫緩收錄該地點。 |
| 交通 | 提供經核實的到達方法，細節不足時只列相應官方交通指引。缺資料可省略分項。 |
| 重要注意事項 | 只在有來源時列出，例如山徑情況、臨時安排或場地的寵物限制。提示「精選資料供出行參考，最新安排請查閱官方資訊。」／“Curated information for planning. Check official sources for the latest updates.”。 |
| 官方資料 | 顯示來源機構及頁面名稱，有實際核對日期才顯示。優先開啟當前語言的官方連結。只有另一語言可用時，在連結上標示「英文」或 “Chinese”。 |
| 變動資訊 | 介面不展示未核實的開放狀態、票價、等候時間、餘量、活動日期、入口或無障礙設備。正式內容內的交通及注意事項標明資料性質，最新安排由官方連結承接。 |

### 導航與行山

- **目的地已核實。** 顯示「導航前往」／“Get directions”。點按前可辨識具名目的地及用途，例如「目的地 · 場地位置」／“Destination · Site location”。可復用 Apple 地圖／Google Maps 選擇及開啟方式。使用已驗證的經緯度或官方目的地，外部地圖決定路線。返回 App 後保留詳情捲動位置。
- **目的地未核實、缺失或因安排暫停使用。** 整個導航區省略，官方資料及交通指引仍可閱讀。連結開啟失敗在原頁顯示雙語提示並容許重試。
- **行山。** 區分路線名稱、觀景點、起點、終點與可導航目的地。經核對所選行程、方向、具名起點、官方資料及座標用途，才可接入「前往起點」／“Directions to trailhead”。山脊或觀景點、路線線段中心、沿途巴士站均不能充當登山入口。龍脊此稿只示範官方資料入口。

## 4. 首頁銜接與返回

| 入口 | 目標及返回 |
| --- | --- |
| 首頁「行山郊遊」 | 沿用 `/explore?category=hiking`。開啟行山列表後點選地點。返回時回到同一分類、卡片及捲動位置。 |
| 首頁「海濱景點」 | 沿用 `/explore?category=waterfront`。後續行為與行山相同。 |
| 首頁「瀏覽更多」 | 沿用 `/explore?category=`，顯示全部精選。 |
| 龍脊及西九首頁精選卡 | 確認對應地點前，維持現有靜態展示及「瀏覽更多」入口。待 UI-05C 核實地點及權利後，以同一穩定內容 ID 產生首頁摘要並連到同一詳情。若候選未通過審核，可改為分類入口，移除與未收錄地點綁定的描述。西九須先確認具體場地及顯示名稱，避免把整個文化區和藝術公園當作同一個導航目的地。 |

建議 UI-05C 以 `/explore/place/[id]` 作根 Stack 詳情的候選設計，`/explore` 繼續指向探索 Tab。推入詳情時保留列表頁；原生返回和邊緣手勢復原原列表或原首頁，並將 VoiceOver 焦點還給原卡片。由外部連結直接打開時若沒有上一頁，返回可落在探索列表。分類變更時由對應列表頂部開始，從詳情返回時保持原捲動位置。切換語言使用相同地點 ID 和分類鍵。未知分類參數回到全部精選；無法解析的地點 ID 顯示安全的不可用狀態。

## 5. 雙語、長文字與無障礙

- 沿用 `useLanguage` 的香港繁中、English 和跟從系統。介面字串進現有 i18n。每項地點需有審核過的中英文標題、地區、簡介與必要交通或安全資料。單語官方連結可清楚標語言。缺乏關鍵翻譯的內容暫緩上架。
- 標準字級下分類兩欄，空間不足時改成單欄或自然增高。英文如 “Hiking & outdoors” 可以換行。長地名、交通段落及官方資料允許換行。大字下插畫可縮小或改為文字上方的色帶，內容高度自適應。
- 使用原有系統字體，頁面標題約 34pt，詳情名稱約 32pt，區塊標題 20–22pt。正文用 `colors.text` 或 `colors.muted`，連結以海港青及外部連結圖示辨識。控制需有可見的按下及焦點狀態。正文和輔助小字以至少 4.5:1 為驗收目標。
- VoiceOver 依標題、簡介、分類、列表、底部導覽順序閱讀。分類朗讀名稱和選中狀態，卡片朗讀名稱、類別、地區和特色，箭頭與抽象圖案從閱讀順序隱藏。官方連結朗讀機構及外部開啟提示。每項觸控區至少 44×44pt，分離相鄰操作。安全區保留原生返回和系統手勢，在最大可用字級確認末項能捲至浮動 Tab 上方。

## 6. 空狀態、初始讀取及異常

| 狀態 | 畫面與行為 |
| --- | --- |
| 分類沒有已收錄地點 | 「這個分類暫無地點。」／“This category has no places yet.”，保留分類及列表標題右側的「查看全部」。 |
| 內容包正常但無有效收錄 | 「暫無探索地點」／“No places to explore yet”，顯示原有空狀態卡。 |
| 本機初始讀取 | 同步讀取時直接顯示內容。若實際存在短暫等待，顯示「正在載入精選地點」／“Loading featured places”及輕量進度提示。勿將等待期間視作空分類。 |
| 內容讀取失敗 | 「暫時未能載入探索資料」／“Couldn’t load Explore content”，若可重新讀取才提供「重試」／“Try again”。其他主 Tab 可繼續使用。 |
| 詳情 ID 無效或內容已移除 | 「此地點資料暫不可用」／“This place is unavailable”，提供返回探索，避免顯示殘留資料或導航。 |
| 離線 | 列表、分類、詳情、已收錄交通說明均可閱讀。官方網頁或外部地圖開啟失敗時提示仍可在此頁查看本機內容。 |
| 官方安排有變或來源待重核 | 顯示簡潔來源提示。發布時若已知目的地不宜使用，移除相應導航；保留可核實資料與官方公告連結。 |

## 7. UI-05C 實施邊界及驗收

1. **內容整理。** 確定首批名單與穩定 ID，逐筆核對雙語資料、分類、交通、官方頁面及來源日期。導航資料另核對具名目的地、座標及用途。素材另記權利及署名。設計稿文字不得直接匯入正式資料。
2. **列表、詳情及入口。** 接入隨 App 發佈的靜態內容，按現有分類鍵篩選，處理空狀態與未知 ID。驗收四個分類名稱、首頁兩個快捷入口和「瀏覽更多」，以及原生返回與手勢返回能恢復分類和捲動位置。確認「查看全部」僅在篩選時顯示，詳情的「精選看點」位於簡介與交通之間。
3. **導航及回歸。** 用核實與未核實目的地各驗一例。行山另驗路線、起點與目的地使用不同欄位。檢查連結／地圖開啟失敗、離線資料、繁中和英文、窄屏、大字、VoiceOver 及安全區。回歸附近、收藏、巴士與其他三個 Tab。
4. **範圍確認。** 不新增設施詳情、探索收藏、即時活動、地圖搜尋、SQLite 遷移或後端。地區先作標示，不加地區篩選。

- 龍脊的行程版本、起點及座標用途，西九藝術公園的場地身份、兩語官網、交通與導航目的地，均待內容階段核對。本輪以 UI-05A 的官方來源紀錄作為線索。
- 請審閱四類雙欄控制、列表密度、無照片插畫方向，以及詳情頁底部的有／無導航版型。三張高保真為繁中，英文及大字的自適應規格需在 UI-05C 實機驗收。
- 首批正式名單、兩語內容及照片權利待定。既有首頁圖片的授權與新用途須分開核對。[首頁圖片來源](../assets/home/credits.md)
