## 1. 本轮用户体验的最终要求

### 1.1 首页附近 Tab 顶部

- 页面标题「附近生活設施」、右侧 Info 署名入口保持原样。
- **删除** UI-04A+1 在顶部搜索框右边新增的定位圆形按钮。
- 原搜索框横向填满其可用宽度，保留内部放大镜图标；点击后进入搜索模式并能真正输入文字。图标处可作为输入框的一部分，不额外添加重复搜索图标按钮。
- 搜索框未选择地点时：`搜尋地點或設施` / `Search places or facilities`。
- 有已确认中心时：显示可读标签，例如 `洪水橋輕鐵站`、`中環碼頭`、`目前位置`、`地圖中心附近`；**选择结果后不能仍显示空占位文字**。
- 查询编辑态：显示用户正在输入的关键词；提供清除输入（×）和取消编辑。清除关键词**不能自动清除已确认搜索中心或把地图重置到默认位置**。
- 地图右下角**恢复唯一的圆形定位按钮**，使用原有海港青／浅底，44pt 以上触控区，避开地图 attribution、底部设施预览卡、悬浮 Tab；必要时随预览卡调整垂直位置。
- 定位行为复用 UI-04A+1：点击才可请求未授权用户的前台权限，单次定位、超时／精度／香港范围检查、旧请求隔离，成功后更新已确认搜索中心；不可开启持续后台定位。
- 列表模式不绘制地图定位浮钮。用户可通过搜索层显式的「使用目前位置」行动回到 GPS；不得为了列表方便而在顶部重新加一个常驻定位圆按钮。
- 不改变已批准的分类标签、全宽地图／列表切换、卡片、外部导航及悬浮 Tab 样式。

### 1.2 真正可输入的搜索

从顶部搜索框打开可输入的搜索层（全屏／modal 均可，优先复用现有导航）。键盘自动聚焦时应正常输入繁中、英文和数字，避免图二仅展示假文本框。

不输入关键词时展示：
- 「使用目前位置」动作（按需授权，不自动请求）；
- **原有七个官方核验地标**，与 UI-04A+1 使用同一坐标源，允许直接选择；
- 可给最近一次选择的地点适度排序，但不新增无根据的历史持久化。

输入关键词时，在同一结果屏按来源分组，建议优先级：
1. **已收录设施**（本地离线：FEHD 960 + AFCD 167，沿用 `source + officialId`；搜索繁中／英文设施名、官方地区文字、可用地址；统一归一化空格大小写，不能丢掉原名）；
2. **原有七个地标**（本地离线）；
3. **香港地点**（地政总署 Location Search API 实际返回的街道、大厦、地区与地点；在线）。

样例分组标题：`設施`、`常用地標`、`香港地點`；英文 `Facilities`、`Landmarks`、`Hong Kong places`。**高保真第二张图中的「中環碼頭」是说明分组的占位例子，不代表「交易廣場」会匹配「中環碼頭」；真实输入时必须按关键词过滤，不能显示无关地标充数。** 没有结果不伪造，分别显示「沒有符合的本地設施」及线上服务状态，不能把网络失败等同于不存在地点。

### 1.3 选择结果后的地图和列表

- 选择「地标／香港地点」：校验经纬度→设置可读 `searchCenterLabel`→确认 `committedSearchCenter`→程序化移动地图中心→重算设施距离→关闭搜索层。只要新中心已明确选择，不需要再点「搜尋此區域」。
- 选择「设施」：以**对应官方设施坐标**移动地图；保留真实 `source + officialId` 并选中该设施，使地图预览卡或相应列表行准确高亮。搜索框显示设施名称；搜索中心更新为当前明确选择的设施坐标，列表按新中心排序。不能匹配到另一家机构的同名记录。
- 点击右下角地图定位按钮：成功后搜索框显示 `目前位置`，已确认中心为 GPS 位置；不把精确 GPS 轨迹持久化或上传。
- 用户手动拖动地图：沿用 UI-04A+1 的 `visibleRegion`、手势判定和「搜尋此區域」机制；**不要因为地图动了就悄悄覆盖搜索中心或搜索栏文字**。仅点击「搜尋此區域」后，标签改成 `地圖中心附近`，设施距离基准更新。
- 地图 → 列表 → 地图：保持已确认中心、来源身份、分类、地图视口和滚动位置；从外部导航返回不重置。
- 列表用一条紧凑说明表示中心，例如 `搜尋中心：中環碼頭 · 按直線距離排序`。说明当前数据距离的参考点，不新增大型卡片。
- 在尚未完成的在线请求、动画或定位请求返回时，**用户最近一次明确选择**拥有最高优先级；旧请求不准改写地图、关键词或选中设施。

## 2. 官方在线地点搜索核验（先做小范围实际预检）

官方文档：`https://portal.csdi.gov.hk/csdi-webpage/apidoc/LocationSearchAPI`

官方接口格式：

`https://www.map.gov.hk/gs/api/v1.0.0/locationSearch?q=<URL-ENCODED-KEYWORD>`

开发前实际用「中環」「旺角」「沙田」及英文地点关键词测试 HTTPS 状态、JSON 字段、中文/英文返回、空结果和错误响应。真实记录及字段以**当日实测**为准，不得根据设计图造数据。

该接口说明只确认 `q` 查询参数和 JSON 响应；**不要凭空加入 `lang` 参数**。如果某些结果仅返回一种语言，保留官方原文并给出合理的来源提示，禁止机器猜译后当作官方名称。

### 2.1 坐标是阻断级要求

官方 `locationSearch` 的返回结果可能包含 HK1980 / HK80 平面坐标 `x`、`y`（Easting / Northing），不是 WGS84 纬度经度。

- 完整解析响应后，按其实际坐标参考系统转换至 WGS84（MapKit `latitude, longitude`）。
- 优先复用仓库已验证的地标 HK1980→WGS84 转换实现。如不适合客户端，须用经过验证的轻量转换函数或官方转换服务；不得将 `x/y` 原样传给 MapKit。
- 构造至少 3 个香港已知点的转换回归测试；检查经纬度范围及实际地理位置正确，不允许仅通过宽松的“在香港范围内”校验。
- 若字段和坐标含义不明确，**停止启用在线地点结果并报告问题**，保留本地搜索，不要上线错误定位。

### 2.2 请求调度与数据最小化

- 本地搜索每次输入立即运行。
- 在线搜索：至少 2 个有效字符，约 400ms 防抖；输入变化时隔离或取消旧请求；限制并发、结果条数和缓存体积。
- 官方文档警告不得短时间大量请求；**不要虚构官方限流配额**。429/5xx/超时/断网时采用温和退避、明显的“在线地点暂不可用”状态，不阻断本地结果。
- 仅按用户主动输入的关键词发起网络搜索。**不要把精确设备 GPS、私人搜索轨迹或完整地图视口发送至在线地点搜索**。
- 内存短期缓存可用；不强制增加 SQLite 迁移，尤其禁止把精确 GPS 搜索日志长期保存。
- 查询长度、格式、URL 编码和 JSON schema 必须有效校验，不能因为单项 malformed 造成整个搜索页崩溃。
- 检查官方接口服务的使用条件与所需署名：在现有 Info 或合适非重复入口注明香港地点搜索资料来自地政总署；不隐藏原 Apple Maps 署名。
