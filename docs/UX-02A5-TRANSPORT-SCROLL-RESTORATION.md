# UX-02A5 附近交通返回後保留瀏覽位置

實作及自動化驗證已完成。iPhone 原生捲動像素及返回手勢待開發者驗收。

## 原因

`/transport` 使用 Expo Router 根 Stack。附近路線、車站及搜尋結果以 `router.push` 開啟各自的詳情，原交通頁仍在 Stack 內。自動化路由檢查顯示 `GO_BACK` 與 `POP` 均返回同一路由實例。

捲動位置丟失發生在交通頁內。返回時，原 UX-01A 回焦定位先清空舊 GPS 參考位置。結果由參考位置物件與距離範圍比對，因而暫時變成空列表，使原生捲動範圍縮短。定位成功後原程式又遞增 `referenceRevision`，而附近 `FlatList` 的 key 含該值。React 因此建立新列表，並從頂部開始。頁內搜尋原本已有同一查詢的資料狀態及獨立列表 key。

## 修正與返回行為

以保留已掛載的列表為主。被動回焦與回前景定位期間保留有效 GPS 結果，收到新座標時沿用同距離範圍的結果，直到新查詢完成。最新失敗確認後顯示原有錯誤與恢復入口。主動改選地標或重取位置按原 UX 流程工作，已取消的定位結果仍由原請求檢查攔截。

| 場景 | 行為 |
| --- | --- |
| 附近路線或車站返回 | 保留列表 key、交通方式、按路線／按車站及範圍。結果順序與可視條目前的資料相同時，使用原生捲動位置。 |
| 頁內搜尋結果返回 | 保留查詢字串、交通方式及列表。清空、取消或改詞使用既有查詢變更行為。 |
| 定位或目錄更新改變列表次序 | 優先跟隨刷新前可視範圍內最前且仍有效的條目。路線用營辦商、方向及服務變體識別，可跟隨同一服務的建議上車站變更。車站用穩定的站點組 ID，搜尋用目錄路線 ID。 |
| 原可視條目消失 | 使用新列表中最接近原索引的有效位置。若虛擬列表未量度目標列，根據原偏移及列表提供的平均行高作一次近似定位。 |
| 用戶主動操作 | 類別、瀏覽模式、距離或參考位置變更使用新的列表範圍。搜尋詞變更清除舊的條目定位。開始拖曳或慣性捲動會取消待執行調整。 |

需要調整時，提交新資料後在下一個畫面幀對原列表執行一次定位。頁面失焦會暫停畫面幀，回焦後仍可處理有效的待辦調整。ETA 同一批資料的時鐘或到站更新沿用現有可視條目監聽。版面、內嵌搜尋、巴士卡片及收藏流程繼續使用 UX-02A4 實作。

## iPhone 驗收

1. 已授權定位時，從首頁「交通查詢」進入，設定「巴士」及 1 公里。由第 10 至 15 條路線開啟詳情，分別點按返回及使用邊緣手勢，確認原卡片仍在可視範圍且可繼續捲動。
2. 在「按車站」由中段進入站點詳情，確認返回後保留範圍、分段及位置。可展開其中一個同名分組重試。
3. 輸入有多筆結果的查詢，捲動至中段開啟路線詳情，核對返回後仍是同一查詢與瀏覽區域。清空、取消、變更距離及切換交通方式後核對新結果。
4. 在回焦或回前景時觀察定位與 ETA。座標相近、結果順序相同時核對原位置。若排序變更，核對靠近原可視條目，並確認開始手動捲動後畫面不被拖回。
