# Phase 4D1 · 专线小巴收藏、首页置顶与 SQLite v11

基线为 `develop` 的 `d88f80c`，与本机 `origin/develop` 对齐，开工工作区干净。本阶段开放专线小巴收藏及置顶。收藏与置顶分别操作，巴士、港铁、轻铁和专线小巴共用三个首页位置。 [4D0 审计](PHASE-4D0-UNIFIED-FAVORITES-AUDIT.md)

## 迁移与旧数据

- v11 在原有 Expo SQLite 独立事务内新增 `gmb_favorites` 并替换小型置顶关联表。历史迁移以及旧收藏表、旧键和旧时间戳不作改写。有效置顶按旧位置保留相对顺序并压紧。
- 对 v10 已缺失收藏目标的巴士或铁路置顶，先把原位置、模式、旧键及 `missing_favorite` 原因写入本地 `home_pin_v11_orphans`，再将这些行排除在新表之外。现有收藏即使官方目录已变化，仍保留原记录及有效置顶。迁移失败会回滚审计表、置顶表、触发器及数据库版本，原文件可重新打开和重试。
- 置顶表限制全局位置 1 至 3，并对引用列的互斥形状和目标唯一性作约束。Repository 在同一写队列及事务中查目标和重排，重排用删后重新插入。SQLite 触发器阻止孤立插入及直接更新置顶行，阻止改写已置顶收藏的业务身份，并在收藏删除时清理置顶。没有依赖 Expo 事务连接上的外键设置。
- 旧库和有效的旧备份通过原有打开流程前向升级。同版本开启不会重复迁移。没有新增备份功能。测试使用已关闭数据库的副本模拟恢复，iOS 的系统备份恢复仍待真机验收。

## 收藏、首页和门禁

收藏键由官方 `route_id / route_seq / stop_seq / stop_id` 四项组成，并保存双语站名和方向终点快照。跨区同号、运营变体及同一站点不同停靠均保留独立身份。用户从路线详情展开具体站次后保存。官方站序末站及离线官方索引中明确只供落车的停靠不显示收藏按钮。路线停靠 API 本身不提供独立上车标志，未匹配的中途停靠按该方向站序判断。

收藏页新增「專線小巴 / Minibus」，复用现有置顶快键、实心图钉、首页位置及更多菜单。移位按全局邻居计算，满额沿用现有提示。取消置顶保留收藏，删除收藏即释放对应置顶。收藏与首页均可直达路线、方向和停靠，保存的站名及站序在离线时仍可显示。

首页只为已置顶的小巴刷新。每轮先用既有缓存核对官方方向站序及精确停靠，再读取官方 ETA。身份变化时保留收藏和置顶并提示重新选择。重复停靠的 ETA 归属无法由官方回应证实时显示说明，收藏本身仍可操作。计划班次显示官方时间及计划标签，过期、超时、无预报、停用和限流沿用现有状态。共享刷新在失焦或进后台时取消订阅，防止静态查询返回后继续启动 ETA 请求。实际请求合并、响应体超时及 429 冷却策略由既有客户端处理。

电车保持 4C4 默认关闭，港九小轮保留原生产授权门禁。收藏和置顶的正式类型中没有这两类，深链接仍由既有详情门禁处理。未改动两者的静态数据或业务实现。

## 验证

`npm run typecheck`、160 项定向回归、iOS Metro／Hermes 生产静态导出和 `git diff --check` 均通过。另逐段比对 v1–v10 的迁移 SQL，内容不变。

SQLite 用固定样本验证旧版本链、三种孤立置顶的审计和释放、故障注入回滚、同版本重启和副本恢复。并发重复保存、四类共享上限、跨模式移动、取消置顶、删除清理、跨区同号／变体／循环线身份均有回归。双语测试覆盖详情收藏、VoiceOver 标题、44 pt 目标、精确导航和混合首页顺序。刷新用模拟时钟验证前后台、超时、官方退避、过期和站点变更。电车及渡轮生产门禁回归一并执行。

## iPhone 人工验收

1. 从有旧收藏和旧置顶的 v10 副本升级，核对原有收藏完整、有效置顶相对顺序一致。使用含孤立置顶的测试副本时，确认空出的名额可置顶小巴。
2. 分别收藏同号跨区路线以及循环线的可上车停靠。进入「專線小巴」确认站序、方向和站名，点卡返回精确站次。确认收藏本身不会置顶。
3. 混合置顶小巴、巴士和铁路，核对满额提示、跨类型换位及重启后的顺序。取消置顶后查看收藏仍在，删除收藏后查看首页位置已释放。
4. 用繁中、英文、VoiceOver 和大字号检查收藏、图钉、位置、更多菜单和首页预报状态与时间呈现。检查进入后台及返回首页、断网和恢复时的状态。生产配置用旧电车及渡轮链接复核不可用回退。
